# 添加应用广告规则

## 项目约定与授权

- 此技能仅用于所在的 subscription-template 项目；从技能所在路径定位仓库，不依赖固定盘符。
- 用户已授权：后续提供需要添加的 App 名称，即执行规则添加、构建、提交并推送，无需再次询问推送许可。该授权不包含强制推送、删除已有应用规则或修改仓库权限。
- 订阅 ID 固定为 `58713126`，不要重置为模板 ID，也不要为每次新增应用生成新 ID。
- 预期远程为 `RLWS/subscription-template`，目标分支为 `main`。执行前核对实际远程与分支；如不匹配，先确认目标，不盲目向其他仓库推送。
- 默认只添加广告规则，不添加权限提示、更新提示、登录授权、支付设置等功能规则；保持现有全局规则配置。
- 用户要求许可暂不阻塞此次工作流。仍记录真实来源与许可状态，不编造授权，不将缺少许可证写成已获许可。

## 选择与导入

1. 查看仓库指令、Git 状态及现有规则。保留已有 App、规则组、订阅元数据和用户未提交的修改；只提交本任务涉及的文件。若相关文件已有用户修改，合并处理并避免将无关修改带入提交。
2. 根据应用名称确定正确包名；普通版、极速版、国际版等有歧义时查询上游信息，仍无法确定再询问。默认京东为 `com.jingdong.app.mall`，淘宝为 `com.taobao.taobao`。
3. 优先查询 `https://github.com/Lin-arm/GKD_subscription` 的 `src/apps/<包名>.ts`；缺少或明显过期时从 `https://github.com/topics/gkd-subscription` 寻找仍维护的来源。读取实际源码，不凭空生成选择器。将引用锁定到取得的提交 SHA，记录获取日期。
4. 审查规则组内容，通常保留 `开屏广告`、`全屏广告-*`、`局部广告-*`；名称只是初筛，仍检查动作是否属于广告跳过或关闭。排除自动登录、自动确认收货、开通支付等功能行为。广告组中关闭推荐弹窗的操作可以保留，但要检查其实际动作与适用页面。
5. 将规则写入 `src/apps/<包名>.ts`，使用项目现有 `defineGkdApp` 格式。`batchImportApps` 自动导入，不需要逐个注册。保留原来的 group/rule key、Activity 限制、排除选择器、冷却与次数限制、快照和示例链接。解析 TypeScript 时使用可靠的结构化方式或人工审查，避免靠不可靠的文本截取损坏嵌套规则。
6. 对已有应用合并或更新，保留本地自定义规则，避免重复 key 和重复导入。上游额外依赖或分类引用需适配当前项目，不照搬整份订阅。
7. 在应用文件中注明上游文件链接，在 `THIRD_PARTY_NOTICES.md` 增补每个来源的提交、日期、筛选范围与许可状态；保留已有来源记录。

## 验证与发布

- 缺少依赖时安装；避免无关锁文件或依赖升级。
- 对修改文件运行格式化和 ESLint，运行 `pnpm run check`，通过后运行 `pnpm run build`。构建负责更新 `dist` 中的订阅、版本信息与说明文件，不直接手改生成内容，也不手动猜测版本号。
- 当前历史环境为 Node 22.15，加载 `prettier.config.ts` 可能报 `ERR_UNKNOWN_FILE_EXTENSION`。此时可仅在当前进程设置 PowerShell `$env:NODE_OPTIONS = '--experimental-strip-types'`（保留已有选项），再运行检查及 Git 命令，使钩子和工作进程继承。优先采用项目声明的 Node 版本；不绕过 Git 钩子来掩盖失败，不为了该兼容问题改动业务配置。
- 解析 `dist/gkd.json5` 和 `dist/gkd.version.json5`，确认两者 ID 均为 `58713126`、版本一致、目标 App 有广告规则组、既有 App 未丢失。检查新增规则没有混入功能组或新全局规则。
- 查看最终 diff，暂存本任务的规则、来源记录及构建产物，提交清晰的 Git 消息，然后 `git push origin main`。若远程领先，先 fetch 并审查变更，再做普通合并或 rebase，重新验证；禁止 force push。认证、分支保护或无法安全解决的冲突需要报告具体阻碍，不重复无效尝试。
- 推送完成后确认结果和工作区状态。不额外触发发布工作流或创建 Release，除非确有必要或用户要求；已推送的 `dist/gkd.json5` 就是远程订阅文件。
- 最终用中文简报新增 App、规则数量、检查结果、提交链接，以及手机可使用的订阅地址：`https://raw.githubusercontent.com/RLWS/subscription-template/main/dist/gkd.json5`。静态校验成功不代表手机实测成功，未测试时明确说明。
